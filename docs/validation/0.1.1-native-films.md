# Validation native macOS 0.1.1, Films

## Objet et prérequis

Ce protocole prépare la validation manuelle de la stabilisation native Films de `0.1.1`. Il est à exécuter dans une fenêtre macOS réellement lancée par Tauri, par exemple avec `npm run tauri:dev` depuis la racine du dépôt, ou depuis le bundle `Sylloge.app` construit nativement.

Une page ouverte à l'adresse d'un serveur Vite, en développement ou en prévisualisation, peut afficher l'interface React, mais ne prouve pas le pont natif. Elle ne suffit donc pas à valider l'accès SQLite via le plugin Tauri, les commandes `invoke` ni les dialogues macOS de sélection et d'enregistrement de fichiers. Les tests ci-dessous doivent être menés dans la fenêtre native, sans inspecter ni manipuler directement `sylloge.db`, son WAL ou son SHM.

Préparer avant de commencer :

- un profil local dont l'état initial est noté, notamment son nombre de profils et de films ;
- un emplacement de travail choisi pour l'export JSON ;
- un éditeur de texte simple pour créer le fichier JSON invalide de l'étape 8 ;
- le titre de test unique `QA 0.1.1 Film persistant`, puis le titre modifié `QA 0.1.1 Film modifié`.

Les libellés ci-dessous correspondent à l'interface actuelle. En cas de défaut, remplir la section de rapport sans le corriger pendant ce parcours.

## Protocole manuel

1. **Ouvrir la fenêtre Tauri native et relever l'état de départ.**

   Démarrer Sylloge dans sa fenêtre native macOS. Dans `Profils et JSON`, noter le nombre de profils affichés, le nom du profil courant et son nombre de films, puis revenir à `Films`. Ne pas utiliser une fenêtre de navigateur reliée seulement à Vite.

   Résultat attendu : la fenêtre affiche la bibliothèque locale et le profil courant. L'état de départ permet de vérifier qu'un import invalide n'ajoute rien et qu'un import valide ajoute exactement un profil.

2. **Créer un film de contrôle.**

   Dans `Films`, choisir `Ajouter un film`. Saisir le titre `QA 0.1.1 Film persistant`, conserver le statut `À découvrir`, cocher `Ajouter aux favoris`, puis choisir `Ajouter le film`. Ne renseigner aucune URL d'affiche à cette étape.

   Résultat attendu : la fiche du nouveau film s'ouvre. Elle affiche le titre, le statut `À découvrir` et l'indication de favori. Le retour à la bibliothèque montre une carte portant ce titre.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

3. **Fermer complètement l'application, puis la relancer nativement.**

   Quitter la fenêtre Sylloge, par exemple avec `Commande + Q`. Relancer ensuite la même cible native macOS, pas une page Vite dans un navigateur. Revenir si nécessaire dans `Films`.

   Résultat attendu : `QA 0.1.1 Film persistant` est toujours présent après la relance, avec son statut et son favori. La relance lit donc la bibliothèque locale existante.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

4. **Modifier le film relu.**

   Ouvrir `QA 0.1.1 Film persistant`, choisir `Modifier`, remplacer son titre par `QA 0.1.1 Film modifié`, choisir le statut `Terminé`, renseigner le texte personnel `Persistance native confirmée.`, puis choisir `Enregistrer les modifications`.

   Résultat attendu : la fiche réaffiche le titre modifié, le statut `Terminé` et le texte personnel. Le retour à la bibliothèque montre le titre modifié, sans créer une seconde fiche.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

5. **Rechercher puis filtrer.**

   Dans la bibliothèque, saisir `QA 0.1.1 Film modifié` dans la recherche. Vérifier le résultat, puis activer le filtre `Terminés` sans effacer la recherche. Enfin, effacer la recherche et conserver le filtre `Terminés`.

   Résultat attendu : la recherche retourne la fiche de contrôle et le compteur indique un film affiché. Avec le filtre `Terminés`, cette même fiche reste affichée. Après effacement de la recherche, elle reste visible parmi les films terminés du profil courant.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

6. **Tester une affiche absente.**

   Ouvrir la fiche de contrôle sans renseigner d'URL d'affiche. Observer la carte ou la fiche, puis, si nécessaire, revenir dans le formulaire pour vérifier l'aperçu vide sans enregistrer de modification.

   Résultat attendu : l'interface présente le fallback neutre avec `Sans affiche` et le titre du film. La fiche reste lisible et aucune erreur ne bloque la consultation ou l'enregistrement.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

7. **Tester une URL d'affiche cassée.**

   Choisir `Modifier`, saisir `https://example.invalid/sylloge-0-1-1-poster.jpg` dans `URL directe de l'affiche`, puis enregistrer. Attendre le résultat du chargement de l'image dans l'aperçu ou la fiche.

   Résultat attendu : l'URL HTTP valide est enregistrable même si l'image distante ne se charge pas. Après l'échec de chargement, l'affichage revient au fallback `Sans affiche` avec le titre du film, sans filtre, teinte, recadrage ni blocage de la fiche.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

8. **Supprimer le film de contrôle.**

   Depuis sa fiche, choisir `Supprimer ce film`, puis confirmer avec `Supprimer définitivement`. Revenir à la bibliothèque, conserver la recherche et le filtre si cela aide à constater l'absence, puis les réinitialiser.

   Résultat attendu : une confirmation explicite précède la suppression. Après confirmation, l'application revient à la bibliothèque et `QA 0.1.1 Film modifié` ne figure plus dans la recherche ni dans les films terminés du profil courant.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

9. **Exporter le profil courant.**

   Ouvrir `Profils et JSON`, choisir `Exporter en JSON`, sélectionner l'emplacement préparé et accepter le nom proposé `sylloge-films-AAAA-MM-JJ.json`. Ouvrir ensuite le fichier exporté dans un éditeur de texte, sans le modifier, et vérifier ses clés de tête.

   Résultat attendu : l'interface annonce que l'export est enregistré et indique le nombre de films du profil courant. Le fichier est du JSON lisible contenant `"format": "sylloge-films"` et `"version": 1`. Il reflète la bibliothèque après la suppression, donc il ne contient pas le film de contrôle supprimé.

   Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

10. **Refuser un JSON invalide sans écriture.**

    Dans l'éditeur de texte, créer un fichier nommé `sylloge-0.1.1-invalide.json` dont l'unique contenu est :

    ```json
    {"format":"sylloge-films",
    ```

    Dans `Profils et JSON`, choisir `Choisir un JSON Sylloge` et sélectionner ce fichier. Ne pas chercher à confirmer l'import, car il doit être bloqué.

    Résultat attendu : l'aperçu indique `Import bloqué`, expose une erreur indiquant que le fichier ne contient pas un JSON valide et précise qu'aucune donnée n'a été écrite. Aucun bouton `Créer le nouveau profil et importer` n'est proposé. Le nombre de profils et le profil courant restent ceux relevés avant ce choix.

    Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

11. **Importer l'export valide dans un nouveau profil.**

    Choisir à nouveau `Choisir un JSON Sylloge`, sélectionner le fichier produit à l'étape 9 et contrôler l'aperçu avant écriture. Choisir ensuite `Créer le nouveau profil et importer`.

    Résultat attendu : l'aperçu est `Valide` et annonce le nombre d'entrées lues. Après confirmation, le rapport `Import terminé` indique le fichier lu, le nouveau profil courant, le nombre de films importés, que le profil source est laissé intact et que les identifiants locaux sont recréés. La liste contient exactement un profil de plus que lors de l'état initial.

    Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

12. **Fermer et relancer après l'import.**

    Quitter complètement Sylloge, puis relancer la même cible Tauri native macOS. Ouvrir `Profils et JSON` puis `Films`.

    Résultat attendu : le profil créé par l'import est toujours disponible, est indiqué comme ouvert et la liste contient toujours un profil de plus qu'à l'état initial. Son nombre de films correspond au rapport de l'étape 11. Le profil source n'a pas été écrasé.

    Résultat : [ ] PASS  [ ] FAIL  [ ] NON TESTÉ

## Couches concernées, établies à partir du code lu

| Flux vérifié | Interface et domaine | Persistance et pont natif |
| --- | --- | --- |
| Création, modification, suppression et relance | `src/main.tsx`, `src/components/FilmForm.tsx`, `src/components/FilmDetail.tsx`, `src/domain/filmForm.ts` | `src/data/filmsRepository.ts`, `src/data/database.ts`, migrations `src-tauri/migrations/0001_create_profiles_and_films.sql`, `0002_create_default_profile.sql` et `0003_track_current_profile.sql` |
| Recherche et filtres | `src/main.tsx`, `src/domain/film.ts` | `src/data/filmsRepository.ts` |
| Affiche absente ou cassée | `src/components/FilmForm.tsx`, `src/components/FilmDetail.tsx`, `src/components/Poster.tsx` | L'URL est enregistrée avec le Film par `src/data/filmsRepository.ts` |
| Export JSON, choix de fichier et import | `src/components/Portability.tsx`, `src/domain/libraryTransfer.ts`, `src/data/libraryTransferService.ts` | `src/data/nativePortability.ts`, `src-tauri/src/lib.rs`, `src-tauri/src/portability.rs`, `src/data/filmsRepository.ts` |
| SQLite, migrations et profil courant après relance | `src/main.tsx` | `src/data/database.ts`, `src/data/filmsRepository.ts`, `src-tauri/src/database.rs`, migrations `0001`, `0002` et `0003` |

La fenêtre native est nécessaire pour les commandes `pick_import_json`, `save_export_json` et `import_library_atomically` appelées depuis `src/data/nativePortability.ts`. Elles sont enregistrées côté Rust dans `src-tauri/src/lib.rs`. Le fichier `src-tauri/src/portability.rs` réalise le dialogue macOS, l'écriture de l'export et la transaction SQLite de l'import.

## Invariants non négociables à contrôler

- SQLite reste locale. La base active, son WAL et son SHM ne sont ni synchronisés ni copiés pendant que l'application est ouverte.
- Un import invalide est refusé avant toute écriture.
- Un import valide crée un nouveau profil. Il ne fusionne ni n'écrase silencieusement le profil source.
- L'export JSON reste lisible et versionné, avec le format `sylloge-films` et la version `1`.

## Rapport de défaut reproductible

Pour chaque résultat `FAIL`, créer une entrée distincte avec les éléments suivants :

1. Étape du protocole et action précise effectuée.
2. Comportement observé, mot pour mot pour les messages visibles si possible.
3. Résultat attendu indiqué dans ce document.
4. Données de test minimales : profil concerné, titre du film, statut, URL d'affiche ou contenu exact du JSON, selon le cas.
5. État avant et après l'action : nombre de profils, profil courant et nombre de films.
6. Capture d'écran, enregistrement d'écran ou logs éventuels, avec le moment exact de la capture.
7. Caractère reproductible : nombre d'essais, conditions de relance et résultat de chaque essai.

Ne pas corriger un défaut pendant cette validation. Le signaler avec ces éléments, puis laisser l'arbitrage du correctif à un lot distinct.
