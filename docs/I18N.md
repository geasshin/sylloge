# Langues de l'interface

Décision d'Aurélien du 23 octobre 2026 : Sylloge existe en français et en anglais, dans l'application comme sur le site (`sylloge-web`). Ce document décrit le comportement attendu, la manière d'écrire un texte et les contrôles qui empêchent une traduction oubliée.

## Comportement

- **Premier lancement** : la liste `navigator.languages` de la webview est parcourue dans l'ordre. La première langue prise en charge l'emporte (`fr`, `fr-CA`, `fr_CH`… donnent le français ; `en`, `en-GB`… l'anglais). Aucune des deux : anglais. La détection seule ne mémorise rien.
- **Choix manuel** : Paramètres › Général › Langue, et le premier écran du premier lancement, avant même la création du profil. Le choix est mémorisé sur l'appareil (`localStorage`, clé `sylloge-language`, valeurs `fr` ou `en`), pour tous les profils, hors sauvegarde de profil. Une valeur inconnue est ignorée.
- **Changement immédiat** : sans rechargement ni remontage. Un brouillon de formulaire, un nom saisi ou une opération en cours ne sont pas perdus. `<html lang>` suit la langue.
- **Données de la personne** : jamais traduites. Titres, auteurs, résumés, avis, notes, citations, noms de profils et noms de vues enregistrées restent tels quels, même quand ils valent « En cours » ou « Tous ». Les valeurs stockées (statuts comme `en cours`, catégories comme `série télé`, formes d'art, identifiants de bibliothèque) restent françaises dans la base et dans les exports ; seul leur libellé affiché est traduit.
- **Dates et nombres** : `formatDate` et `formatNumber` (fr-FR ou en-GB). Les dates `AAAA-MM-JJ` sont des jours calendaires, sans décalage de fuseau.
- **Métadonnées** : les nouvelles recherches TMDB demandent la langue de l'interface. Une fiche déjà associée garde les métadonnées déjà enregistrées.
- **Dialogues natifs** : le titre et le filtre des sélecteurs de fichiers et de dossiers suivent la langue (paramètre `language` des commandes Tauri, français par défaut). Les contrôles système suivent le système.

## Écrire un texte

Le français est la langue source : la clé de traduction est la phrase française exacte.

| Besoin | Écriture |
|---|---|
| Texte fixe | `t('Ajouter une fiche')` |
| Valeurs | `t('Ouvrir la fiche de {title}', { title })` ou ``t`Ouvrir la fiche de ${title}` `` (clé `Ouvrir la fiche de {0}`) |
| Même mot, deux sens | `tc('comics', 'Dessin')` : clé de catalogue `comics\u0004Dessin` ; sans entrée contextuelle, la traduction simple s'applique |
| Message déjà composé par le domaine, les données ou le natif | `translateMessage(error.message)` : retrouve un gabarit du catalogue (`La colonne « {0} » n’existe pas dans le fichier.`) et laisse les valeurs capturées intactes ; message inconnu : inchangé |
| Date, nombre | `formatDate(valeur, options)`, `formatNumber(n)`, `getLocale()` |
| Composant mémoïsé ou `useMemo` qui contient du texte traduit | `useLanguage()` (`src/i18n/react.ts`) et la langue dans les dépendances |

Règles :

1. Traduire au rendu. Une constante de module reste en français et se passe dans `t(...)` à l'affichage, sinon le changement de langue ne la touche pas.
2. Pas de pluriel bricolé par suffixe : deux clés explicites (« 1 fiche » et « {count} fiches »).
3. Un libellé anglais ne doit pas déborder là où le français tient sur une ligne : le raccourcir plutôt que d'ajouter un retour à la ligne ou une ellipse.
4. Ne pas toucher aux contrats : en-têtes CSV, clés JSON, noms de fichiers d'export, valeurs d'options.

## Catalogues

`src/i18n/core.ts` (API), `src/i18n/react.ts` (hook), `src/i18n/catalog.ts` (fusion) et `src/i18n/catalogs/` :

| Fichier | Contenu |
|---|---|
| `main.ts` | application racine : navigation, bibliothèques, cartes |
| `home.ts` | accueil, calendrier, bibliothèques personnalisées et leurs modèles |
| `entries.ts` | fiches détail, formulaires, validation des formulaires |
| `transfers.ts` | import, export, guides |
| `shell.ts` | réglages, profils, sauvegardes, mises à jour, premier lancement |
| `views.ts` | barre de vues, listes déroulantes, recherches fournisseur |
| `messages.ts` | messages du domaine et de la couche données |
| `native.ts` | messages d'erreur écrits par le code Rust |
| `shared.ts` | textes partagés et clés contextuelles |

Une phrase n'a qu'une traduction : deux catalogues qui se contredisent font échouer `scripts/i18n-catalog.test.mjs`.

## Contrôles

`npm run test:i18n` (inclus dans `npm run verify`) :

- `i18n-catalog.test.mjs` : chaque `t()`, `tc()` et ``t`…` `` des sources a une traduction ; mêmes placeholders des deux côtés ; aucune traduction vide ; aucune contradiction entre catalogues.
- `i18n-state.test.mjs`, `i18n.test.mjs` : détection, mémorisation, stockage refusé, interpolation, contexte, `translateMessage`, dates.
- un fichier par domaine (`i18n-main`, `-home`, `-entries`, `-transfers`, `-shell`, `-views`, `-messages`, `-native`, `-native-messages`) : rendu anglais réel des composants, contenu de la personne intact.

Recette navigateur : `qa-app.html?lang=fr` (défaut, pour les scripts `qa-*.js` écrits avec les libellés français), `?lang=en`, ou `?lang=auto` pour exercer la détection réelle. `scripts/qa-language.js` couvre le parcours.

## Limites connues

- Les messages d'erreur natifs et du domaine sont traduits par correspondance avec le catalogue : un message absent reste en français. Les listes sont dans `messages.ts` et `native.ts`.
- Le site (`sylloge-web`) garde ses captures d'écran en interface française, annoncées comme telles.
- Une troisième langue demanderait de changer le modèle de catalogue (français vers anglais) : non prévu.
