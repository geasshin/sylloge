# Sylloge 0.3.0 — lot interne 2 : Accueil modulaire Films-only

> **Statut :** prêt pour implémentation. Ce lot transforme l’Accueil minimal en composition culturelle pleine page, sans inventer de données ni de médias non encore pris en charge.
>
> **Branche :** `release/0.3.0-settings-updates`

## Résultat utilisateur

L’Accueil devient une surface éditoriale de consultation, pas une page d’actions ni un dashboard. À une taille desktop de référence en plein écran, la composition principale tient dans le viewport sans défilement de page. Elle présente des modules fondés exclusivement sur les données Films locales réelles, mais dont la structure pourra devenir transversale lorsque les autres médiums existeront réellement.

## Données et sémantique

Le modèle courant ne contient que Films. Aucun Livre, Jeu, Série ou œuvre d’Art fictif ne doit être affiché.

- **Vus récemment** : jusqu’à quatre Films `terminé` ayant une date `watched_at`, ordonnés de la date de visionnage la plus récente à la plus ancienne. Un film terminé sans date ne prétend pas être récent.
- **Favoris** : jusqu’à quatre Films marqués `is_favorite`, avec un ordre déterministe utile et sans score inventé.
- **Films vus** : calendrier compact des cinq dernières semaines ; un jour est marqué seulement lorsqu’au moins un Film terminé est daté ce jour-là. Plusieurs films le même jour sont annoncés textuellement aux technologies d’assistance. La couleur actuelle représente uniquement Films ; la légende multi-médiums est reportée jusqu’à l’existence de ces médias.
- **Module contextuel** : afficher des Films `en attente` lorsqu’il y en a ; sinon afficher les Films ajoutés récemment. Il doit toujours s’appuyer sur les champs existants et dire explicitement ce qu’il montre.

Une collection vide affiche un état éditorial sobre, sans données de démonstration et sans bouton d’ajout sur l’Accueil.

## Composition et règles visuelles

- Organiser les modules dans une grille desktop asymétrique, avec **Vus récemment** comme surface principale, **Favoris** et le calendrier comme contrepoints, et le module contextuel comme surface complémentaire.
- Conserver Archive calme : fond clair chaud, espace négatif, bordures fines, typographie Syne seulement pour les titres, affiches intactes, aucun gradient, glassmorphism, métrique de performance, streak ou badge de gamification.
- L’Accueil ne contient plus les actions Ajouter un film et Parcourir Films. Ces actions restent accessibles depuis Films.
- À une fenêtre de référence de **1440 × 900 px** avec sidebar affichée, le contenu principal est entièrement visible sans scroll vertical, sans texte masqué et sans dégradation des contrôles. À des hauteurs plus faibles, privilégier une adaptation lisible plutôt qu’une compression illisible ; un scroll local peut rester le repli honnête.
- Les modules restent adaptés aux fenêtres plus étroites : aucune largeur forcée, aucun débordement horizontal, titres longs et affiches manquantes traités correctement.
- Ne pas présenter les modules comme une promesse déjà multi-médiums. Les libellés sont honnêtes tant que Films est le seul médium réel.

## Exclusions

- aucun changement SQLite, migration, format JSON, sauvegarde, profil, import ou API ;
- aucun nouveau médium ni contenu de remplacement ;
- aucune nouvelle dépendance ;
- aucune modification de l’updater, des permissions Tauri, de la signature, de la version ou du pipeline GitHub ;
- aucun commit, merge, tag ou push.

## Critères d’acceptation

1. L’Accueil affiche quatre surfaces cohérentes à partir des seuls Films réels : Vus récemment, Favoris, Films vus et module contextuel.
2. Chaque module vide explique sobrement l’absence de données correspondantes ; aucun exemple fictif n’est inséré.
3. Les règles de sélection respectent les champs réels `status`, `watched_at`, `is_favorite`, `created_at` et ne créent aucune donnée.
4. Les cartes et affiches réutilisent les fallbacks accessibles existants ; les dates et libellés restent lisibles avec du contenu long ou incomplet.
5. À 1440 × 900, sidebar comprise, la surface principale n’exige pas de scroll vertical ; l’interface se replie proprement aux dimensions plus contraintes sans débordement horizontal.
6. La navigation vers Films, Paramètres, fiches et formulaires ne régresse pas.
7. `npm run typecheck`, `npm run verify`, `npm run build`, `cargo fmt --check`, `cargo check`, `cargo test` et `cargo clippy --all-targets -- -D warnings` restent verts.

## Preuves manuelles macOS

1. ouvrir `npm run tauri:dev` à 1440 × 900 et vérifier l’absence de scroll sur l’Accueil ;
2. vérifier un profil avec Films datés, favoris, en attente et sans affiche ;
3. vérifier un profil vide et un profil où aucun film n’a de date de visionnage ;
4. parcourir la navigation et les éléments de l’Accueil au clavier ;
5. réduire la fenêtre jusqu’à une taille contrainte et vérifier absence de débordement horizontal et contenu encore lisible.
