# Sylloge 0.3.0 — lot interne 1 : Accueil et architecture Paramètres

> **Statut :** implémenté et revu automatiquement ; QA native macOS encore requise avant tout commit. Ce document borne le premier lot interne du jalon `0.3.0` ; il ne constitue pas une release publique ni une mise à jour de version.
>
> **Branche :** `release/0.3.0-settings-updates`

## Résultat utilisateur

La navigation distingue clairement la collection Films, une page **Accueil** calme et une page **Paramètres**. L’Accueil est un point d’entrée éditorial minimal pour le profil local et ses deux actions principales. Paramètres remplace l’ancienne entrée « Profils et JSON » et regroupe sans ambiguïté les réglages locaux existants.

Une personne peut continuer à ouvrir un autre profil, exporter ou importer un JSON et gérer ses snapshots avec le comportement existant ; aucun de ces flux ne doit changer de garantie.

## Décisions et périmètre de ce lot

- Ajouter une page Accueil distincte de Films, qui affiche le profil courant, un repère local minimal sur la collection et des actions pour ajouter un film ou parcourir Films. Ce n’est ni un dashboard ni une page de statistiques.
- Remplacer l’entrée de navigation « Profils et JSON » par **Paramètres**, avec une icône accessible et un libellé clair.
- Créer une page Paramètres structurée en sections sobres : **Profils**, **Données et sauvegardes**, **Application** et **À propos**.
- Réorganiser les capacités existantes sans les réécrire : sélection de profil dans Profils ; export JSON, import contrôlé et snapshots dans Données et sauvegardes.
- Dans Application et À propos, afficher uniquement des informations locales exactes. L’état des mises à jour doit dire explicitement que ce mécanisme n’est pas encore configuré. Aucun bouton, faux contrôle ou promesse de téléchargement ne doit être ajouté.
- Conserver tous les comportements existants : SQLite locale, import dans un nouveau profil avec validation avant écriture, sauvegardes JSON explicites et absence de synchronisation de la SQLite active.

## Exclusions explicites

- pas de création, renommage ou suppression de profil dans ce lot ; la suppression demande une décision complémentaire sur le devenir des snapshots externes enregistrés ;
- pas d’onboarding ; il nécessite un état de premier lancement persistant et un plan de migration dédié ;
- pas d’updater, de release signée, de réseau, de GitHub Releases, de clé, de permission Tauri ou de dépendance supplémentaire ;
- pas de changement du schéma SQLite, des migrations, du format JSON, des règles d’import/export, des snapshots ou des actions Films ;
- pas de changement de version, commit, merge, tag ou push.

## Fichiers prévisibles

- `src/main.tsx` : navigation et vues Accueil / Paramètres ;
- `src/components/Portability.tsx` : découpage de l’ancienne surface vers les sections Paramètres, sans modification de logique métier ;
- `src/styles.css` : styles accessibles, cohérents avec Archive calme ;
- éventuellement un ou deux composants frontend étroits si cela réduit la complexité de `src/main.tsx`.

## Critères d’acceptation

1. Au lancement d’une bibliothèque existante, la navigation permet d’ouvrir Films, Accueil et Paramètres ; l’élément actif est lisible et exposé via `aria-current`.
2. L’Accueil affiche le nom du profil courant, le nombre réel de films et deux actions fonctionnelles : ajouter un film, parcourir Films. Il ne crée ni donnée ni métrique inventée.
3. Paramètres affiche les quatre sections demandées. Les profils existants peuvent toujours être ouverts depuis cette page et l’état courant reste explicite.
4. Export, import JSON validé dans un nouveau profil, choix de dossier de sauvegarde et sauvegarde manuelle restent accessibles depuis Données et sauvegardes, avec les mêmes garanties et messages d’erreur.
5. Application / À propos ne contient aucun contrôle de mise à jour actionnable tant qu’aucune release signée n’existe ; le texte indique que la recherche de mise à jour n’est pas encore configurée.
6. Retour, focus clavier, libellés, états de chargement et messages d’erreur restent accessibles. Aucun look dashboard, donnée fictive, dépendance ou permission nouvelle.
7. `npm run typecheck`, `npm run verify`, `npm run build`, `cargo fmt --check`, `cargo check`, `cargo test` et `cargo clippy --all-targets -- -D warnings` restent verts.

## Preuves manuelles macOS attendues après revue

1. lancer `npm run tauri:dev` avec une bibliothèque existante ;
2. parcourir Accueil, Films et Paramètres au clavier ;
3. ajouter un film depuis Accueil et confirmer sa présence dans Films ;
4. ouvrir un autre profil depuis Paramètres, puis vérifier le profil courant dans Accueil et Films ;
5. exporter un JSON, refuser un JSON invalide et constater qu’aucune écriture n’a lieu ;
6. vérifier les sections Application / À propos et l’absence de faux bouton de mise à jour.
