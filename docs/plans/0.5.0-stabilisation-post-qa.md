# Stabilisation post-QA du train 0.5.0 — plan d’implémentation

> **Pour Hermes :** exécuter ce plan directement, un jalon interne à la fois. Avant chaque jalon, établir un brief borné, écrire les preuves attendues, implémenter, relire le diff, exécuter les gates techniques, puis attendre la validation visible d’Aurélien. Ne pas déléguer le code à un agent externe.

**But :** transformer les retours de la première recette manuelle en une séquence de corrections et de refontes vérifiables, sans masquer les nouvelles décisions produit derrière un unique « correctif 0.4.9 ».

**Architecture :** conserver SQLite comme source de vérité locale et le document JSON versionné comme enveloppe de portabilité. Mutualiser les composants d’import/export sans gommer les contrats propres à chaque médium. Les formats utilisateur supportés sont JSON et CSV ; un ZIP ou un dossier peut seulement servir de conteneur dans lequel Sylloge détecte ces formats. Séparer la fiabilité TMDB, l’expérience TMDB, les formats tabulaires, l’inspection bornée des conteneurs et les vues avancées afin d’éviter une refonte transversale impossible à relire.

**Stack :** React 19, TypeScript, Vite, Tauri 2, Rust, SQLite, API TMDB, JSON, CSV et conteneurs ZIP/dossiers locaux.

## 1. Diagnostic et décisions actées

### 1.1 Ce qui relève d’un défaut avéré

- Le flux de création assistée TMDB ne transmet pas les métadonnées du candidat au formulaire. Dans `src/main.tsx`, la confirmation renvoie vers `create` sans conserver le candidat ni des valeurs initiales. Le comportement observé par Aurélien est donc cohérent avec le code actuel : ce n’est pas une erreur de manipulation.
- Le flux d’association d’une fiche existante quitte visuellement la fiche, ouvre une page de recherche vide et oblige à ressaisir le titre.
- La résolution de plusieurs centaines de doublons ne dispose ni d’une recherche, ni d’actions persistantes en haut de la boîte de dialogue.
- Un dossier de snapshots supprimé depuis Finder reste enregistré dans les réglages, et aucune commande ne permet actuellement d’effacer ce réglage.
- Le chevauchement du bouton de création de profil et le focus violet disproportionné sont des défauts d’interface visibles. Le focus ne doit toutefois pas être supprimé : il doit être redessiné pour rester accessible.

### 1.2 Ce qui était une limitation contractuelle et devient une nouvelle exigence

- Films accepte actuellement JSON, CSV et un ZIP historiquement nommé « Notion ». Séries, Livres, Jeux et Art acceptent uniquement le document JSON de bibliothèque. C’est explicitement le comportement codé et documenté au jalon `0.4.4`, pas une panne du sélecteur.
- Ajouter CSV aux quatre autres médiums modifie donc le contrat produit, le mapping, la validation et les tests. Cela doit être construit à partir de leurs champs réels, pas en copiant les colonnes Films.
- Le vocabulaire et le contrat « import Notion » sont abandonnés. Les ZIP et dossiers deviennent de simples conteneurs bornés : Sylloge y cherche des JSON ou CSV compatibles et demande un choix si plusieurs candidats sont trouvés. Le support historique Film peut continuer à utiliser les pages Markdown présentes dans certains ZIP pour préserver les notes déjà prises en charge, sans en faire un format public général.
- Les tris avancés, filtres combinables et vues personnalisées étaient reportés au train `0.6.0`. Le retour QA les promeut dans le train actif ; les vues enregistrées impliquent probablement une nouvelle migration SQLite et une décision de portabilité.

### 1.3 Clarifications techniques

- **La base active est SQLite, pas MySQL.** Les fiches, profils, réglages et caches sont stockés dans une base SQLite locale.
- **Export JSON :** création manuelle d’un fichier pouvant contenir une collection ou les cinq collections du profil courant selon l’action choisie.
- **Import JSON :** lecture d’un JSON compatible dans la collection visée ou, pour un document à cinq collections, dans un profil vide. Ce n’est pas une restauration du fichier SQLite brut.
- **Snapshot :** même famille de document JSON, créée manuellement ou automatiquement dans un dossier choisi. Le dossier et le dernier jour de snapshot automatique sont des réglages SQLite.
- **CSV :** format tabulaire lisible et interopérable, adapté aux exports unitaires par médium ; il ne remplace pas le JSON pour une restauration complète fidèle.
- **Vocabulaire d’interface :** l’utilisateur voit seulement Importer, Exporter, JSON, CSV et Snapshots. En interne, le schéma JSON doit rester identifié et versionné (`sylloge-library`, version 2 actuellement), sinon les migrations et la rétrocompatibilité deviennent invérifiables.
- **Suggestions TMDB :** elles ne seront pas préchargées localement. L’application appellera la recherche TMDB après une courte temporisation quand l’utilisateur tape, avec seuil minimal, annulation logique des réponses obsolètes et possibilité de lancer une autre recherche.
- **Actions présentes à deux endroits :** les bibliothèques et les Paramètres doivent afficher les mêmes capacités, mais utiliser les mêmes composants et services. Il ne faut pas maintenir deux implémentations divergentes.
- **ZIP et dossiers :** ils ne constituent pas de nouveaux formats de données. Ils sont inspectés avec des limites de profondeur, taille et nombre de fichiers pour trouver des JSON/CSV. Les autres fichiers sont ignorés, sauf compatibilité Film historique explicitement testée.

## 2. Convention de versionnement retenue

Ne pas utiliser `0.4.9.1` : quatre segments ne correspondent pas au Semantic Versioning documenté dans `docs/WORKFLOW.md`. Ne pas utiliser `0.4.91`, qui rend la lecture du train ambiguë.

Les nouveaux points de contrôle deviennent des **jalons d’intégration internes séquentiels** : `0.4.10`, `0.4.11`, etc. Ils ne modifient ni les manifestes, ni le tag public. La release installable reste `0.5.0`.

Le jalon `0.4.9` reste la première livraison technique de cohérence multi-médiums, mais sa validation humaine est interrompue par la QA. Il n’est pas considéré comme validé.

## `0.4.14` — Architecture claire des imports, exports et sauvegardes

**État :** implémenté dans le code et couvert par les gates TypeScript, vérification statique, build et Rust. La recette native des parcours Importer/Exporter reste à exercer sur l’application Tauri avant de clôturer la validation humaine.

### Décision d’interface

Les Paramètres deviennent un hub fonctionnel, pas une liste descriptive :

1. **Importer** — JSON ou CSV, pour une collection ou les cinq collections selon le fichier ;
2. **Exporter** — JSON ou CSV selon la portée et le médium ;
3. **Snapshots** — choix, changement et désactivation du dossier de copies JSON datées.

Chaque bibliothèque conserve Importer et Exporter, mais réutilise exactement les mêmes composants de capacité que les Paramètres.

### Périmètre

- Retirer de l’interface le terme générique « format Sylloge » et éviter aussi le jargon « export complet » / « restauration complète » dans les titres d’action. Utiliser Importer, Exporter, JSON, CSV et Snapshots.
- Expliquer seulement au moment utile qu’un JSON à cinq collections s’importe dans un profil vide et qu’un snapshot est un JSON daté dans un dossier.
- Supprimer le bloc purement informatif « Collections disponibles / import par médium » s’il n’offre aucune action.
- Afficher pour chaque médium les actions réellement disponibles et leurs formats.
- Harmoniser les actions entre l’en-tête de bibliothèque et les Paramètres via des composants partagés.
- Conserver en interne le discriminant et la version du document JSON.

### Fichiers pressentis

- `src/components/Portability.tsx`
- `src/components/LibraryImportButton.tsx`
- nouveaux composants sous `src/components/` pour les capacités de transfert partagées
- `src/domain/libraryDocument.ts`
- `src/domain/libraryTransfer.ts`
- `src/data/libraryTransferService.ts`
- `src/main.tsx`
- `src/styles.css`
- `README.md`
- `docs/QA_MANUELLE_0.5.0.md`

### Acceptation

- Depuis les Paramètres ou une bibliothèque, un même médium affiche la même matrice de formats et appelle le même service.
- L’utilisateur sait avant de cliquer si l’action concerne une collection ou les cinq collections du profil.
- Export complet, restauration complète et snapshots ne sont plus présentés comme trois variantes indifférenciées.
- Le JSON v1/v2 historique reste réimportable.

- Critères spécifiques : catégorie Série/Livre, auteur, plateforme Jeu, forme/artiste/lieu/exposition pour Art, réalisation pour Film.
- Combiner texte, plusieurs filtres et un tri.
- Afficher les critères actifs, le nombre de résultats et une action « Réinitialiser ».
- Conserver les critères lors d’un aller-retour vers une fiche.
- Ne pas exposer « le plus de paramètres possible » sans borne : seuls les champs utiles et indexables entrent dans le contrat.

### Fichiers pressentis

### Acceptation

- Texte + plusieurs filtres + tri produisent le même résultat après relance de l’application.
- Les paramètres SQL sont liés, jamais interpolés.
- Réinitialiser ramène à une vue clairement définie.
- Une bibliothèque vide ou sans résultat conserve un parcours de sortie.

**Objectif unique :** permettre de nommer, rappeler, renommer et supprimer un couple filtres + tri.

### Gate produit et données

Avant la migration, décider si les vues font partie :

1. de la base locale uniquement ;
2. des snapshots ;
3. de l’export complet de restauration.

Si elles deviennent portables, déterminer si le JSON v2 peut les recevoir de façon compatible ou si une version de document suivante est requise. Cette décision est obligatoire avant le code.

### Périmètre

- Ajouter une table de vues par profil et par médium, probablement via `src-tauri/migrations/0012_create_saved_views.sql`.
- Stocker un schéma de critères validé et versionné, pas du SQL.
- Créer, appliquer, renommer et supprimer une vue.
- Gérer les noms vides, doublons et vues devenues invalides après évolution du schéma.

- Une vue survit au redémarrage.

# 7. Points encore conditionnels

- **Compatibilité Film historique :** les pages Markdown déjà exploitées dans certains ZIP restent prises en charge, mais Markdown n’est pas promu en format public.
- **Sélection de dossier :** elle donne un accès ponctuel au dossier choisi ; elle ne crée aucune surveillance, synchronisation ou permission permanente.
- **Citations en CSV :** représentation à arbitrer au brief `0.4.15`.
- **Portabilité des vues enregistrées :** à trancher avant la migration `0.4.21`.
- **Filtres exacts par médium :** le brief `0.4.20` doit retenir les critères utiles, pas exposer mécaniquement toutes les colonnes SQLite.
- **Nouvelle QA :** tout retour ultérieur peut insérer de nouveaux jalons `0.4.23+` avant la release publique.
